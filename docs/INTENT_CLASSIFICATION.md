# Intent classification output

The intent export separates original data, extracted values, and generated labels:

| Column | Meaning |
|---|---|
| `source.*` | Original Cosmos JSON fields |
| `extracted.user_text` | User text selected by the program |
| `extracted.user_text[messages[].data.content]` | Selected text when it came from the nested message path |
| `extracted.user_text.source` | Actual path used, including fallback paths |
| `classification.intent` | Intent assigned by the rules engine |
| `classification.rule` | Stable identifier of the rule that assigned the intent |
| `classification.reason` | Human-readable explanation |

## Rules

Rules are evaluated from top to bottom. The first match wins.

| Rule | Intent | Condition |
|---|---|---|
| `ticket.active_workflow` | `ticket` | A prior record in the same CID started a ticket workflow |
| `ticket.explicit_reference_or_action` | `ticket` | Ticket/case/incident ID or create/update/close/escalate action is present |
| `modify.configuration_change` | `modify` | Change, configuration, enable/disable/reset, setup, activation, installation, or provisioning request |
| `rca.issue_diagnosis` | `rca` | Troubleshooting, investigation, root-cause, connectivity, outage, failure, or dropping-service language |
| `query.customer_question` | `query` | Focused lookup or verification question with customer/device context |
| `general.non_customer_question` | `general` | General explanation, policy, procedure, or definition without customer context |
| `clarification.missing_user_text` | `clarification_needed` | An issue exists but no user request could be extracted |
| `clarification.no_rule_match` | `clarification_needed` | User text exists but no higher-confidence rule matched |

The CSV also includes `classification.confidence`, `classification.needs_human_review`, `classification.version`, and `classification.classified_at`, all generated by the program.

## Time-range export

Use timezone-aware `--start-time` and optional `--end-time` arguments to classify
only source documents whose Cosmos-managed `_ts` is inside the inclusive window.
If the end is omitted, the process start time is used.

```powershell
python intent_app.py `
  --start-time "2026-09-04T18:00:00+05:30" `
  --end-time "2026-09-09T18:00:00+05:30"
```

The missing-record audit, when enabled, is constrained to the same timeframe.

## Unique CID counts by intent

Every run creates a second CSV report controlled by `INTENT_COUNT_OUTPUT`. The
default name is the main output stem followed by `_counts.csv`. It contains:

| Column | Meaning |
|---|---|
| `classification_intent` | Generated classification intent or `ALL_INTENTS` |
| `classified_record_count` | Number of classified Cosmos source records |
| `unique_cid_count` | Number of distinct non-empty conversation IDs |

The `ALL_INTENTS` row counts each CID once across the entire run. Within the
intent rows, a CID is counted once per intent, so a CID classified under different
intents contributes once to each of those rows. The report follows the same
timeframe and `INTENT_MAX_RECORDS` scope as the main classification output.

To compare separately generated old-data and Friday-to-yesterday CSVs, run:

```powershell
python intent_count_report.py `
  --dataset "old_data=C:\path\old_intent_labels.csv" `
  --dataset "friday_to_yesterday=C:\path\friday_to_yesterday_labels.csv" `
  --output "intent_cid_count_report.csv"
```

The comparison app recognizes `conversation_id`, direct `cid`, nested
`source.messages`, and `test.py`'s flattened `message.data.cid`. It does not
modify either input CSV.
